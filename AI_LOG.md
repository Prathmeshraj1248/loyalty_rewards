# AI Log

I used an AI assistant (Claude) as a development partner, working phase by phase: planning, architecture, database, backend, customer portal, admin dashboard, claiming, redemption, security, tests, and documentation. The prompts below are summaries of what I asked. I ran, tested, and checked the code myself, and I can explain every part.

**Summary: 9 interactions. Entries 4, 5, 6 and 8 are cases where the AI was wrong.**

---

## 1. Planning the project (decision)

**Prompt:** I gave the assignment and asked the AI to act as a senior engineer and build the system in 10 phases, explaining everything simply, testing each step, and never faking results. I described my idea: a unique QR per product box, scanned by the customer to earn coins, coins convert to rupees.

**What the AI did:** It restated my idea and pointed out a weakness: a QR on the *outside* of the box could be scanned in a shop without buying.

**My decision:** I chose to place the QR **inside** the box, and kept 1 coin = ₹1 and request-then-approve redemption. This is documented in `ASSUMPTIONS.md` (#1, #6, #8).

## 2. Choosing the stack (decision)

**Prompt:** Which stack, given that I know PHP?

**What the AI did:** It compared plain PHP with Laravel and recommended plain structured PHP, because I must explain every line.

**My decision:** Plain PHP with PDO, controllers, services, and repositories. Reasons are in `ARCHITECTURE.md`.

## 3. Database and security design (understanding the AI's proposal)

**Prompt:** Design the database and the reward logic so codes cannot be reused or guessed.

**What the AI proposed:** Store only an HMAC hash of each code, keep a point ledger instead of a stored balance, claim in a transaction with a row lock, and add a UNIQUE constraint so a code can earn coins only once.

**What I did:** I asked for the reasons, then checked them: in phpMyAdmin the `product_codes` table shows only 64-character hashes, and the balance is always the sum of ledger rows.

## 4. AI mistake #1: `.gitignore` was never created, so `.env` was pushed

**What went wrong:** The AI gave me the contents of `.gitignore` but never told me to check that the file really existed. I ran `git add .` and my `.env` (with `CODE_HASH_SECRET`) was committed and pushed to public GitHub.

**How I noticed:** I saw `.env` in my GitHub repository.

**How it was fixed:** I created `.gitignore` correctly, ran `git rm --cached .env`, **generated a new `CODE_HASH_SECRET`** (no codes existed yet), and rewrote history with `git filter-branch`. I confirmed with `git log --all --oneline -- .env` (empty).

**Lesson:** Check `git status` before the first `git add .`, and treat a pushed secret as leaked, whatever else is done.

## 5. AI mistake #2: it claimed the history cleanup worked without proof

**What went wrong:** After the `filter-branch` step the AI said the cleanup had worked, based only on a warning message I pasted. It never asked for evidence. In fact GitHub still held the original commit containing `.env`.

**How I noticed:** My next `git push` was rejected with "fetch first". The AI then asked for `git log --oneline --graph --all`, which showed `origin/main` still at the old commit.

**How it was fixed:** `git push --force-with-lease origin main`. I then verified by fetching again: a straight history, `origin/main` at my latest commit, and no `.env` in any commit. The new secret made the old one useless.

**Lesson:** Verify the remote after a force push. Do not infer it.

## 6. Claiming and QR scanning (Phase 6), plus AI mistake #3

**Prompt:** Build the claim flow: the server decides if a code is valid, one code earns coins once, simultaneous scans are safe, and every attempt is logged. This phase was generated in a separate AI chat session.

**What I checked:** I uploaded the whole project to this assistant and asked it to review everything. The claim logic was sound (row lock, conditional update, UNIQUE ledger entry).

**AI mistake #3:** In the batch phase the AI made every QR point to `/scan#CODE`, but no `/scan` route existed, and the claim page had no camera scanner. Scanning a real sticker gave a 404, and camera scanning (an assignment requirement) was missing.

**How it was noticed:** The review compared the QR link generated by the admin controller with the routes in `index.php`, and found no match and no camera code in the claim view.

**How it was fixed:** Added the `/scan` route and an `html5-qrcode` camera button that fills in the code. The customer still presses Claim, so the server stays the only decision maker.

## 7. Proving the security with tests

**Prompt:** Write automated tests for the code checksum, claiming, rate limiting, redemption, and a race test where many requests claim the same code at once.

**Result:** 17 tests, 172 assertions, all passing. The race test starts 8 separate PHP processes that fire at the same instant. Exactly one wins.

**Checking the tests are real:** I deliberately broke the code twice (rate-limit threshold changed to 500, then the `status = 'unused'` condition removed from the claim update). The tests failed both times. After reverting, they passed again. Note: while undoing one of these changes a method (`failureCounts`) went missing from `ClaimRepository.php`, most likely when I restored the file. That was my own slip, found during the final code review, and I added it back.

## 8. AI mistakes #4: small instruction errors that broke the app

Three separate slips in the AI's instructions, each found by a real error on my screen:

| What the AI told me | What broke | How I noticed | Fix |
|---|---|---|---|
| `composer require --dev phpunit/phpunit:^10.5` | In Windows Command Prompt `^` is an escape character, so Composer received exactly `10.5` and refused it for a security advisory | Error screenshot from Composer | Put the package in quotes: `"phpunit/phpunit:^10.5"` |
| "Add these `use` lines at the top" of `DashboardController.php` | I placed them above `namespace`, which is a PHP fatal error, so the admin dashboard crashed | Review of my project files | Rewrote the file with `namespace` first, then the `use` lines |
| "Add a Redeem link to the menu array" in `layout.php` | The edit left out a comma, giving a parse error on every page with the menu | Parse error screen at line 14 | Rewrote the array with one link per line and trailing commas. Added `php -l` as a syntax check habit |

## 9. AI feature design (decision)

**Prompt:** Add AI only where it helps, and never let it approve codes or award coins.

**What was built:** On the admin dashboard, plain rules decide what looks suspicious. An optional button asks an AI model to summarise those signals in plain English. Only anonymous counts are sent (no emails, names, or IP addresses). If there is no API key or the call fails, a rule-based summary is shown. The AI output is text only and is escaped when displayed.

**My decision:** Keep AI out of anything that changes data. Documented in `ASSUMPTIONS.md` (#22).
